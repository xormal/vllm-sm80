# Пять A/B-пар: memory runtime кандидата

Завершены 29.10.2026, 00:08 по Тбилиси. Сравнивались четыре integration-модуля reference `351e4c74b` и default-кандидат с runtime `aef8fa694`, FALLBACK_ROWS=0. Остальной код и CUDA kernels одинаковы. Отдельные compile caches; одинаковый прогрев; порядок baseline→candidate повторён пять раз. Порт 8086, GPU0–1. Невалидный первый reference без зависимостей Clef исключён.

**Результат: краткие quality-пробы эквивалентны; подтверждённого прироста скорости нет; полная приёмка отклонена из-за остановки потока при KV saturation.**

## Качество

- Все пять пар: три базовых чата и четыре смысловые пробы дали одинаковые сообщения и logprobs; top-20 и вычисленные границы энтропии совпали. Ответы Clef и seeded sampling также совпали. Tool-call проверка прошла во всех процессах.
- Повторы одной версии между процессами также совпали в этих коротких пробах. Это ограниченная выборка, не доказательство качества всей модели или полной энтропии распределения.
- Отмена и prefix reuse/max_tokens=1: ответы и logprobs совпали между версиями.
- Свежие prefill8196/8197/8198/16389, solo и mixed: выходные токены совпали. Почти все logprobs точны; максимальное межверсионное отличие на8198 solo — 4,77×10⁻⁷. Поэтому полный bitwise-pass для всех state-проб не заявляется.
- Внутри каждой версии на16389 solo/mixed max|Δlogprob|=0,946765 при одинаковом тексте. Это существующая зависимость от режима выполнения, одинаковая в первой A/B-паре.
- Длинный recall: baseline14/16, candidate16/16; baseline — один повторяющийся ответ, candidate — без найденных повторов. Условие≥900 слов выполнено только3/16 и5/16 соответственно. Порядок HTTP-прихода и batch slots конкурентных запросов не фиксирован, поэтому это не доказанное улучшение от memory-патча.

## Производительность

2048 входных и512 выходных токенов на каждый чат; C8+R4 использует Clef34816. Скорость агрегатная, включая prefill; mixed wall time включает завершение Clef. Числа — геометрические средние пяти запусков. Интервал — парный t95 для log-ratio с4 степенями свободы.

Интервалы предполагают независимые, приблизительно нормальные log-ratios; нулевую потерю скорости они не доказывают.

## Блокирующая проверка

C8×(49147+2048), прежние KV/context/max_num_seqs/K4: baseline731,03 с, candidate729,22 с; оба дали7/8 полных ответов, один поток — два токена и затем600 с молчания до timeout. После отмены выдача оставшихся запросов ускорялась. OOM и падения процесса в этих сериях не было. HTTP-счётчик preemption может запаздывать; число2 не является доказанным полным числом вытеснений.

CPU-repro показывает повторное вытеснение из-за допуска recompute, которому хватает текущего chunk, но не перехода к decode. Диагностика реального гибридного runtime продолжается отдельно: [PREEMPTION_FOLLOWUP.md](PREEMPTION_FOLLOWUP.md).
